The daemon exposes an HTTP API over a Unix socket. The current public contract is `coven.daemon.v1` under the `/api/v1` prefix.

The socket is local by default:

```bash
curl --unix-socket "$HOME/.coven/coven.sock" \
  http://localhost/api/v1/health
```

For the full endpoint reference, see [Coven local socket API](/docs/reference/api). For diagrams of the handshake, event cursors, launch lifecycle, and authority boundary, see [API architecture diagrams](/docs/reference/api-architecture).

## Transports

The Unix socket at `$COVEN_HOME/coven.sock` is the default and recommended transport. The daemon can additionally bind a TCP listener with `coven daemon serve --tcp <addr>`, guarded so it stays local:

- The bind address must resolve to loopback (`127.0.0.1` / `::1`); the daemon refuses non-loopback addresses.
- Each TCP request's `Host` and `Origin` headers must be loopback, or exactly match a host passed via the repeatable `--allow-host <host>` flag (for a trusted reverse proxy that forwards a fixed hostname, such as a Tailscale-served FQDN).
- The API is unauthenticated on both transports, so `--allow-host` should only name hosts fronted by an authenticated transport (Tailscale, SSH). The bind itself stays loopback.

Docs that describe the API as Unix-socket-only are describing the default posture, not a hard limit.

## Health

Every client should begin with:

```http
GET /api/v1/health
```

Expected shape:

```json
{
  "ok": true,
  "apiVersion": "coven.daemon.v1",
  "covenVersion": "0.0.0",
  "capabilities": {
    "sessions": true,
    "events": true,
    "travel": true,
    "scheduler": true,
    "hub": true,
    "executorDispatch": true,
    "eventCursor": "sequence",
    "structuredErrors": true
  },
  "daemon": {
    "pid": 12345,
    "startedAt": "2026-05-09T12:00:00Z",
    "socket": "/Users/example/.coven/coven.sock"
  }
}
```

`daemon` is `null` when process metadata is unavailable. The response may also include an optional `hub` object (`role`, `hubId`, `nodesTotal`, `nodesAvailable`) summarizing the hub control plane; it is omitted when the daemon has no store access.

Clients should branch on `apiVersion`, then use `capabilities` to decide which surfaces to show. `covenVersion` is useful diagnostics metadata, not the compatibility guard.

## Capability discovery

`GET /api/v1/capabilities` exposes the daemon and adapter capability catalog. Use it before hard-coding action ids or assuming a harness is available.

Capabilities can describe:

- Session and event support.
- Event cursor support.
- Structured error support.
- Available harness adapters.
- Control-plane action ids.
- Policy hints for safe, approval-required, or unavailable actions.

## Endpoint families

The stable public v1 core is the narrow session/event/action contract:

| Endpoint | Purpose |
| --- | --- |
| `GET /api/v1/api-version` | Read route-prefix version metadata. |
| `GET /api/v1/health` | Check daemon health and compatibility. |
| `GET /api/v1/capabilities` | Discover daemon and control-plane capabilities. |
| `POST /api/v1/actions` | Route a known control-plane action. |
| `GET /api/v1/sessions` | List sessions. |
| `POST /api/v1/sessions` | Launch a session. |
| `POST /api/v1/sessions/external` | Register an externally-launched session. |
| `GET /api/v1/sessions/:id` | Fetch one session. |
| `GET /api/v1/sessions/:id/log` | Read a rendered log view of one session. |
| `GET /api/v1/sessions/:id/events` | Read one session's events (path-scoped form). |
| `GET /api/v1/sessions/:id/artifacts/:artifactId` | Fetch a sensitive artifact (requires `raw=1`). |
| `GET /api/v1/events?sessionId=...` | Read append-only session events. |
| `POST /api/v1/sessions/:id/input` | Forward input to a live session. |
| `POST /api/v1/sessions/:id/kill` | Kill a live session. |
| `POST /api/v1/sessions/:id/complete` | Complete an externally-registered session. |

New clients should use the `/api/v1` prefix. Early unversioned aliases are compatibility paths, not the contract to build around.

## Control-plane surface map

Beyond the documented v1 core, the daemon serves a broader control plane. **Scope statement:** the narrow session/event/action contract above is the stable public v1; the control-plane routes below are used by first-party clients (Cave, CastCodes) and may evolve without a version bump. Treat them as observable, not as a stable integration surface.

| Threads | `GET /api/v1/threads/weaves`, `GET /api/v1/threads/proposals`, `GET /api/v1/threads/proposals/:id`, `POST /api/v1/threads/proposals/:id/approve`, `POST /api/v1/threads/proposals/:id/reject` |

## Error envelope

All failures should use the structured error envelope:

```json
{
  "error": {
    "code": "session.cwd_outside_root",
    "message": "cwd must canonicalize inside project root",
    "details": {
      "projectRoot": "/Users/me/work/proj",
      "cwd": "/tmp/wander"
    }
  }
}
```

Clients should branch on `error.code`, not message text. Message text can improve human debugging, but codes are the stable behavior surface.

The [full error code table](/docs/reference/api#error-envelope) lists every stable code with its HTTP status, typical cause, and fix; [error code lookup](/docs/reference/troubleshooting#error-code-lookup) maps each code to a troubleshooting walkthrough.

Common classes:

| Code class | Client behavior |
| --- | --- |
| Invalid request | Fix the request shape, route prefix, harness id, project root, or cwd. |
| Not found | Stop assuming the route, session, event cursor, or action id exists. |
| Not live | Switch from live input or kill controls to attach, replay, or diagnostics. |
| Runtime unavailable | Ask the user to inspect daemon status or retry after restart. |

## Versioning rules

`apiVersion: "coven.daemon.v1"` is the named contract. Coven can add fields, endpoints, and capabilities under an existing version. Breaking changes require a new named contract.

Client rule of thumb:

1. Call health.
2. Confirm the named API contract.
3. Read capabilities.
4. Use only supported endpoint families.
5. Handle structured errors everywhere.
