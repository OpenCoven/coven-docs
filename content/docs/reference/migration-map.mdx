# Docs Migration Map

This page tracks the gap between the original `OpenCoven/coven/docs` corpus and the public docs site.

The goal is to keep the docs honest: current runtime behavior should be documented as current, while future hosted APIs, distributed orchestration, and harness handoffs should be labeled as roadmap work until shipped.

## Current Stack to Show

The public homepage should expose the actual Coven runtime stack, not only the familiar-facing abstraction.

```mermaid
flowchart TB
  Surfaces["Clients and surfaces\nCLI/TUI, comux, OpenClaw plugin"]
  Api["Local daemon API\nHTTP over Unix socket, /api/v1"]
  Daemon["Rust Coven daemon\nauthority boundary"]
  Store["SQLite store\nsessions plus append-only events"]
  Harness["Harness adapters\nCodex, Claude Code, future adapters"]
  Pty["PTY execution\nproject root, attach, replay, input, kill"]
  Familiar["Familiar layer\nidentity, memory, tools, policy"]
  Model["Provider model auth\nowned by the harness/provider"]

  Surfaces --> Api --> Daemon
  Daemon --> Store
  Daemon --> Harness --> Pty
  Pty --> Familiar --> Model
```

## Diagram Backlog

### Runtime Topology

```mermaid
flowchart LR
  CLI["coven CLI/TUI"]
  Comux["comux"]
  Plugin["OpenClaw plugin"]
  Socket["HTTP over Unix socket\n/api/v1"]
  Daemon["Rust daemon"]
  Store[("SQLite session ledger")]
  Log[("Append-only event log")]
  Pty["PTY session"]
  Harness["Harness CLI"]

  CLI --> Socket
  Comux --> Socket
  Plugin --> Socket
  Socket --> Daemon
  Daemon --> Store
  Daemon --> Log
  Daemon --> Pty --> Harness
```

### Trust Boundary

```mermaid
flowchart TB
  Client["Same-user local client"]
  Socket["COVEN_HOME/coven.sock"]
  Daemon["Rust daemon enforcement"]
  Deny["Fail closed\nunknown API, cwd, harness, session"]
  Provider["Provider auth\nCodex or Claude owns login"]

  Client --> Socket --> Daemon
  Daemon --> Deny
  Daemon --> Provider
```

### Session Lifecycle

```mermaid
stateDiagram-v2
  [*] --> Created
  Created --> Running
  Running --> Exited
  Running --> Orphaned
  Exited --> Archived
  Archived --> Summoned
  Summoned --> Exited
  Exited --> Sacrificed
  Archived --> Sacrificed
```

### Client Handshake

```mermaid
sequenceDiagram
  participant Client
  participant Daemon
  participant Harness

  Client->>Daemon: GET /api/v1/health
  Daemon-->>Client: apiVersion, ok, daemon metadata
  Client->>Daemon: GET /api/v1/capabilities
  Daemon-->>Client: supported actions and harnesses
  Client->>Daemon: POST /api/v1/sessions
  Daemon->>Harness: spawn PTY
  Daemon-->>Client: session record
  Client->>Daemon: GET /api/v1/events?sessionId=...
  Daemon-->>Client: event page and cursor
```

### Harness Adapter Lifecycle

```mermaid
flowchart LR
  Detect["Detect CLI"]
  Auth["Validate provider auth"]
  Command["Build harness command"]
  Spawn["Spawn PTY"]
  Record["Record output events"]
  Cleanup["Exit and cleanup"]

  Detect --> Auth --> Command --> Spawn --> Record --> Cleanup
```

### Troubleshooting Flow

```mermaid
flowchart TB
  Doctor["Run coven doctor"]
  Command{"coven command found?"}
  Daemon{"daemon reachable?"}
  Harness{"harness installed?"}
  Root{"cwd inside project root?"}
  Session{"session live?"}
  Api{"API version supported?"}
  Ready["Ready to run or attach"]

  Doctor --> Command
  Command -- no --> Install["Install Coven"]
  Command -- yes --> Daemon
  Daemon -- no --> Start["Start or restart daemon"]
  Daemon -- yes --> Harness
  Harness -- no --> InstallHarness["Install Codex or Claude Code"]
  Harness -- yes --> Root
  Root -- no --> FixRoot["Open a valid project root"]
  Root -- yes --> Session
  Session -- no --> Rejoin["Summon or start a new session"]
  Session -- yes --> Api
  Api -- no --> Upgrade["Upgrade Coven or client"]
  Api -- yes --> Ready
```
