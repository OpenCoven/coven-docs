The two most load-bearing words in Coven's vocabulary are also the two easiest to blur. A **harness** is a coding-agent CLI that Coven launches and supervises. A **runtime** is — depending on the qualifier — either Coven itself or the agent process doing the work. This page records the usage rule, the audit that brought the docs in line with it, and the strings that are deliberately exempt.

For the concept boundaries, start at [What is a harness?](/docs/harnesses/what-is-a-harness) and the [Glossolalia](/docs/reference/glossolalia) language map. This page governs how the words are used, not what the components do.

## The two terms

| Term | Meaning in Coven docs | Owned by |
| --- | --- | --- |
| Harness | A supported coding-agent CLI (Codex, Claude Code, Coven Code, Copilot CLI, or an adapter-registered CLI) that Coven runs as a supervised PTY process. | The harness owns its conversation, provider auth, and tool execution. |
| Runtime (substrate sense) | Coven: the daemon, session records, event log, and socket API that harnesses run on. | Coven owns launch validation, PTY lifecycle, and session state. |
| Runtime (agent sense) | The harness or engine process that receives a prompt and works inside the PTY. | The harness or engine owns everything inside its process. |

The senses point in opposite directions across the same boundary: the substrate is what supervises; the agent runtime is what is supervised. An unqualified "runtime" forces the reader to guess which side of the PTY the sentence lives on.

## The usage rule

Both senses are legitimate, and both stay. The rule is that **every use of "runtime" carries a qualifier that pins its sense**:

| Sense | Approved phrasings | Example |
| --- | --- | --- |
| Coven substrate | "local runtime substrate", "Coven runtime", "local runtime", "Rust runtime" | "Coven is the local runtime substrate that harnesses run on." |
| Harness/engine side | "agent runtime", "external agent runtime", "interactive agent runtime" | "Coven Code is OpenCoven's own agent runtime." |
| Model-server side | "local model runtime", "provider runtime" | "Ollama, llama.cpp, or a custom local model runtime." |

Never write the collocations "harness runtime" or "runtime harness" — each one welds the two terms into a phrase that reads as both senses at once. Name the side you mean: "the familiar's harness", or "the agent runtime behind the familiar".

"Harness" needs no qualifier, but it must not absorb its neighbors:

| Do not conflate | The distinction |
| --- | --- |
| Harness vs. adapter | The adapter is Coven's launch spec — the mapping from harness id to executable and fixed args. The harness is the CLI the adapter launches. |
| Harness vs. engine | The engine is the CLI-managed Coven Code harness binary (`coven engine install`). Every engine run is a harness run; not every harness is the engine. |
| Harness vs. familiar | A familiar is the named persona layer (identity, memory, tools, policy). A familiar's work is carried out by harness runs; the familiar is not the process. |
| Harness vs. provider | The provider is the external model or agent service a harness talks to. "Connecting providers as harnesses" is a category error — CLIs connect as harnesses; providers stay behind them. |
| Harness vs. Coven | Coven is not a harness. It is the substrate harnesses run on. |

## The senses of "runtime" in these docs

The audit classified every occurrence into seven senses. The first three are the ones writers choose between; the rest are fixed vocabulary that happens to contain the word.

| Sense | What it names | Status |
| --- | --- | --- |
| Substrate | Coven: daemon, ledger, socket API. | Qualified per the rule above. |
| Agent runtime | The harness or engine process inside the PTY. | Qualified per the rule above. |
| Runtime state | Machine-local records: `.coven/`, sockets, databases, `COVEN_HOME` contents. | Standard usage; keep. |
| API error vocabulary | `runtime_unavailable`, and "session runtime" in its error text. | Pinned; never reword. |
| Platform-technical | Tokio runtime, Next.js `export const runtime = 'edge'`. | Code facts; never reword. |
| Labels and headings | "Runtime Topology", "Runtime boundary", "Runtime Concepts", table keys such as `runtimePath`. | Contextual; keep. |
| Adverbial | "at runtime", "errors at runtime". | Ordinary English; keep. |

### Pinned strings that must never be "fixed"

- **`runtime_unavailable`** — a stable error code in the `coven.daemon.v1` API. Its documented meaning, "the session runtime is unavailable", mirrors the daemon's own `SessionRuntime` naming in Rust. Rewording either would detach the docs from the contract. See the [error envelope reference](/docs/reference/api#error-envelope).
- **Rust identifiers** — `LiveSessionRuntime`, `coven_runtime_spec`, and similar names quoted from the source tree keep their exact casing and wording.
- **Generated OpenAPI pages** — everything under `/docs/openapi` is generated from `openapi/coven.daemon.v1.yaml` and is never hand-edited.
- **The AI-literature note** — [What is a harness?](/docs/harnesses/what-is-a-harness) deliberately contrasts Coven's PTY-adapter sense of "harness" with the broader scaffolding sense in AI research. That contrast is content, not a violation.

## Audit snapshot

Audited 2026-07-21, covering every `content/docs` MDX and meta.json file, homepage and OG-image site copy, and the check scripts: 859 occurrences of "harness" across 85 files and 143 occurrences of "runtime" across 37 files. Site copy needed no changes — every use was already qualified ("Local Runtime", "Rust runtime", "runtime stack" under the substrate heading).

Corrections applied by the audit:

| Location | Was | Now |
| --- | --- | --- |
| Concepts, OpenCoven section | "the ecosystem and organization around the runtime" | "around the Coven runtime" |
| Concepts, capability fields | "`owning adapter` identifies the runtime or adapter" | "identifies the daemon or adapter" (matches the capabilities payload) |
| Changelog v0.1.1 | "through the familiar's own harness runtime" | "through the familiar's own harness" |
| Changelog v0.1.0 | "first-class OpenCode runtime support" | "first-class OpenCode agent-runtime support" |
| Glossolalia, Engine entry | "the engine is CLI-managed runtime" | "a CLI-managed agent runtime" |
| Roadmap, North Star | "autonomous coding runtimes" | "autonomous coding agents" |
| Roadmap, messaging row | "not an OpenCoven dependency or replacement runtime" | "not an OpenCoven dependency or a replacement for the Coven runtime" |
| Memory + Models, local models | "or a custom local runtime" | "or a custom local model runtime" |
| Memory + Models, provider boundary diagram | provider node "local runtime" | "local model runtime" |
| Getting started | "Codex, Claude Code, or any future adapter" | "or any adapter-registered CLI" |
| Familiars, harness adapters | Described providers connecting "as harnesses"; listed two built-in harnesses | External coding-agent CLIs connect as harnesses; all four built-ins plus the trusted `grok` and `hermes` recipes listed |

## Enforcement

`scripts/check-terminology.mjs` runs in the build chain with the other docs checks. It fails the build when a banned collocation ("harness runtime", "runtime harness", "coding runtimes", "providers as harnesses") reappears anywhere outside the generated OpenAPI pages and this page's own examples, and it pins this page, its nav entry, and the qualifier phrases above so the rule cannot silently drift.
