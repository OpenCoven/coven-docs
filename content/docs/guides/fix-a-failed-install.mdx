Install looked fine, but `coven` does not work. This guide walks the triage in the order that finds the culprit fastest. Each step either fixes the problem or tells you exactly which step to jump to. The deep reference behind every fix is [Install debugging](/docs/cli/install-debugging).

## Prerequisites

- A terminal on the machine where the install failed.
- npm if you installed via `@opencoven/cli`, or a Rust toolchain if you built from source.

## Step 1 — Establish what actually runs

```bash
which -a coven
coven --version
```

On Windows, in PowerShell:

```powershell
Get-Command coven -All
coven --version
```

**Expected output:** exactly one path and the version you meant to install. Interpret anything else:

- **No output from `which`** (or `Get-Command` errors) — the command is not on `PATH`; go to Step 2.
- **Multiple paths** — an older install is shadowing the new one; go to Step 3.
- **Runs, but errors at runtime** — install is fine; leave this guide for [Troubleshooting](/docs/reference/troubleshooting).

If `coven` runs at all, run `coven doctor` before anything else — its report usually names the failing layer for you.

## Step 2 — Fix `PATH` for your install method

For an npm global install, confirm npm's global bin directory is on `PATH`:

```bash
npm prefix -g
echo "$PATH" | tr ':' '\n' | grep -Fx "$(npm prefix -g)/bin"
```

On Windows, in PowerShell:

```powershell
npm prefix -g
($env:Path -split ';') | Where-Object { $_ -like "*$(npm prefix -g)*" }
```

**Expected output:** the last command prints the matching `PATH` entry (on macOS and Linux the bin directory is `<prefix>/bin`; on Windows it is the prefix itself). If it prints nothing, add the directory to `PATH` in your shell profile, open a new terminal, and rerun `coven doctor`. Source builds check `$HOME/.cargo/bin` the same way. Avoid `sudo npm install -g` — use a user-writable npm prefix instead.

While `PATH` is broken you can still exercise the published package directly:

```bash
npx @opencoven/cli doctor
```

## Step 3 — Clear stale versions and caches

`npx` caches packages, and old global installs shadow new ones:

```bash
npm install -g @opencoven/cli@latest
which -a coven
coven --version
```

**Expected output:** one surviving path reporting the latest version. If `which -a coven` still lists more than one path, remove the stale copy (or reorder `PATH` so the intended one wins) — see [Wrong or stale version](/docs/cli/install-debugging#wrong-or-stale-version).

## Step 4 — Check the native platform package

The npm wrapper resolves a native package for your OS/CPU as an optional dependency. If npm warned about a missing optional dependency, or the wrapper installed but `coven` will not launch:

```bash
npm view @opencoven/cli version dist-tags
```

**Expected output:** a published version. The wrapper currently targets `darwin-arm64`, `linux-x64`, and `win32-x64`. Two rules:

- Reinstall from the same OS/CPU where you run Coven — copying `node_modules` across platforms skips the native package.
- On an unsupported platform (including Alpine/musl), skip to Step 5 and build from source, or use WSL2 — see [Missing native platform package](/docs/cli/install-debugging#missing-native-platform-package).

## Step 5 — Fall back to a source build

When the published packages cannot serve your platform, or you need unreleased behavior:

```bash
git clone https://github.com/OpenCoven/coven.git
cd coven
cargo build --workspace
cargo run -p coven-cli -- doctor
```

If compilation fails, update the toolchain and retry clean:

```bash
rustup update stable
cargo clean
cargo build --workspace
```

**Expected output:** `cargo run -p coven-cli -- doctor` prints the doctor report. Install it onto `PATH` with `cargo install --path crates/coven-cli`, then confirm with `coven doctor`.

## Step 6 — Verify the repair

Whichever step fixed it, finish with the same two commands:

```bash
which -a coven
coven doctor
```

**Expected output:** one path, and a doctor report whose store and project checks pass. Harness lines may still show `[!!]` — that is the next task, not an install failure; continue with [Connect a harness](/docs/guides/connect-a-harness).

## Troubleshooting

- **Still not found after fixing `PATH`** — you edited the profile but reused the old shell; open a new terminal. See [`coven` command not found](/docs/reference/troubleshooting#coven-command-not-found).
- **npm permission errors on global install** — switch to a user-writable npm prefix or a Node version manager; do not reach for `sudo`.
- **`Unsupported platform` at install time** — your OS/CPU has no published native package; Step 5 is the supported path.
- **Need to file a support report** — collect the evidence list in [Install debugging](/docs/cli/install-debugging#evidence-to-collect).
- **Install works but sessions fail** — that is runtime, not install; start at [Troubleshooting](/docs/reference/troubleshooting).
